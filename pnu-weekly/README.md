# 대학 정책 AI 주간 모니터링 — 작동 프로토타입

KMI 「글로벌 공급망 AI 주간 모니터링」(scm-briefing.kmi.re.kr) 구조를 대학 버전으로 옮긴 것으로,
기능이 실제로 동작하는지 검증하기 위한 프로토타입이다. **수치·기사는 전부 기획용 샘플이다.**

## 벤치마크 원본이 실제로 쓰는 구조

KMI 주간 리포트의 실주소는 `hyongmo.github.io/Global-SCM-Monitoring/weekly_report.html`.
서버도 DB도 없는 **GitHub Pages 정적 HTML 한 장**이다 (8.45MB, 링크 22,912개, `<details>` 382개,
Leaflet 지도 인라인 스크립트 약 100개, PDF는 `pdf/` 폴더의 사전 생성 파일 링크).
이 프로토타입도 같은 방식을 따른다.

## 구조

```
data/weeks.json             주차별 산출물 — 파이프라인의 최종 출력 스키마
data/meta.json              기관 정보, 거점국립대 10곳 좌표
data/sources.json           KPI 원자료 출처 레지스트리 (+ 갱신주기 라벨)
data/indicator-catalog.json 지표 후보 카탈로그 (일/주/월/분기/연 · 전 URL 접속 확인)
src/render.mjs              데이터 → HTML (수치를 만들지 않음. 데이터에 있는 값만 출력)
src/styles.css              화면 + 인쇄(A4) 스타일
src/app.js                  Leaflet 지도, 각주 이동, 스크롤스파이, 인쇄/PDF
build.mjs                   빌드 + 데이터 정합성 검사
pdf.mjs                     헤드리스 Chrome(CDP)로 PDF 사전 생성
dist/index.html             산출물 — 이 파일만 올리면 됨
dist/pdf/*.pdf              사전 생성 PDF
```

## 실행

```bash
node build.mjs   # dist/index.html 생성
node pdf.mjs     # dist/pdf/*.pdf 생성 (Chrome 필요)
```

로컬 확인은 `dist/`에서 정적 서버를 띄운다 (`file://`에서는 PDF 존재 확인 fetch가 막힘):

```bash
cd dist && python -m http.server 8777
```

## 설계상 중요한 두 가지

**1. 수치는 코드가, 서술은 LLM이.**
`render.mjs`는 계산을 하지 않는다. 모든 수치는 `weeks.json`에 이미 집계된 값으로만 존재하고,
LLM은 `summary`/`diagnosis`의 문장만 담당한다. 생성형 AI가 숫자를 만들어내면 공식 리포트로 쓸 수 없기 때문이다.

**2. 지표를 갱신주기로 분리했다.**
KMI는 BDI·유가처럼 매일 움직이는 지표가 있지만 대학 지표는 대부분 연 단위다.
그대로 옮기면 "전주 대비 0%"가 반복되는 죽은 대시보드가 된다. 그래서 화면을 둘로 나눴다.

- **주간 변동 지표** — 수집 기사에서 파이프라인이 직접 산출. 외부 의존 없이 매주 변한다.
- **배경 지표** — 외부 통계. 카드마다 갱신주기 배지(일간/주간/월간/공시/연 1회)를 달아
  언제 바뀌는 값인지 읽는 사람이 바로 알 수 있게 했다.

지표 후보 전체는 `data/indicator-catalog.json` 참조. 2026-09-11 기준 전 URL 접속 확인(HTTP 200).

## 빌드가 막는 오류

`build.mjs`는 다음을 발견하면 빌드를 세운다.

- 중복 주차 id
- 본문 각주 `[n]`에 대응하는 `refs` 항목 없음
- `sources.json`에 없는 출처 키, 정의되지 않은 갱신주기

## 남은 작업

1. **수집 라이선스 확정** — 빅카인즈 유료 전환 여부·단가 문의, 네이버 검색 API 약관(AI 활용 제한) 법무 검토
2. `collect → classify → aggregate → narrate` 파이프라인 구현 (현재는 산출물 스키마만 확정)
3. 일일 브리핑(`daily.html`) — 동일 파이프라인, 주기만 일 단위
4. 학내망 배포 시 지도 타일 대체 (OSM 외부 타일 → 내부 타일 서버 또는 행정경계 GeoJSON)
5. `univ.joongang.co.kr` 응답 없음 — 중앙일보 대학평가 지속 여부 확인

## 빅카인즈 대안 — 수집기 (`collect.mjs`)

빅카인즈가 유료 전환되어, **무료·공개 RSS만으로 수집이 되는지** 실제로 검증한 수집기다.

```bash
node collect.mjs --days 7
```

2026-09-11 실행 결과: **7일간 기사 612건** 수집(중복 제거 후). 인증키 0개, 비용 0원.

| 층 | 소스 | 역할 | 라이선스 |
|---|---|---|---|
| 1차 | 교육부·과기정통부 보도자료, 법안, 공고 | 서술 근거 (전문 인용 가능) | 공공누리 1유형 |
| 2차 | 구글 뉴스 RSS (키워드 9종) | 이슈 탐지·집계 | 제목/매체/날짜만 |
| 3차 | 한국대학신문·교수신문·베리타스알파·대학지 RSS | 각주 원문 링크 | 매체가 직접 배포 |

### 저작권 설계

뉴스저작권은 빅카인즈만의 문제가 아니다. 한국언론진흥재단이 저작권법 105조 신탁관리기관으로
103개 언론사의 뉴스저작권을 관리하며 **625개 공공기관이 뉴스저작권 상품을 이용** 중이다.
즉 크롤링으로 우회해도 기사 본문을 저장·배포하면 같은 문제에 걸린다.

그래서 `collect.mjs`는 **기사 본문을 저장하지 않는다.** 제목 / 링크 / 매체 / 날짜 /
매체가 RSS로 스스로 배포한 요약(200자 절단)만 보관한다. 분류·집계·경보는 이것으로 충분하고,
리포트 본문의 서술 근거는 공공누리 1차 소스에서 가져온다.

**유료 구매 경로는 쓰지 않는다.** 빅카인즈도, 건별 기사 구매(뉴스토어 등)도 사용하지 않는 것이
운영 방침이다. 따라서 기사 본문이 필요해 보이는 상황은 다음 순서로 해소한다.

1. 같은 사안의 **보도자료 원문**을 찾아 인용한다 (대부분의 정책 기사는 부처 보도자료가 원출처다)
2. 법안·공고가 근거면 **의안정보·공고 원문**을 인용한다
3. 그래도 부족하면 **해당 언론사에 직접 이용허락을 문의**한다 (신탁기관 경유 없이 매체와 직접)
4. 어느 것도 안 되면 **그 사안은 제목·링크·건수로만 다룬다** — 서술을 만들지 않는다

4번이 핵심이다. 근거를 못 대면 문장을 쓰지 않는 것이, 출처 없는 서술을 생성하는 것보다 안전하다.

### 알려진 한계

- **구글 뉴스 링크는 리디렉션 URL**(`news.google.com/rss/articles/...`)이라 원문 URL이 아니다.
  브라우저에서는 정상 연결되지만 각주에 원문 주소를 노출하려면 언론사 RSS 쪽 링크를 써야 한다.
- 분류 규칙(`FIELDS` / `RISK`)은 초기값이다. 현재 '기타' 비중이 높고 crisis/warning 경계가
  거칠어, 운영 전 3~4주치 실데이터로 키워드 보정이 필요하다.
- 부산일보·국제신문 RSS 경로는 확인되지 않았다. 지역 이슈 커버리지를 위해 별도 확인 필요.

## 실데이터 주차 생성 (`aggregate.mjs`)

```bash
node collect.mjs --days 7     # 수집
node aggregate.mjs w37        # 집계 + 서술 결합 → weeks.json
node build.mjs && node pdf.mjs
```

`data/narrative/<id>.json` 은 **LLM 산출물이며 숫자를 담지 않는다.** 모든 수치는 `aggregate.mjs`
가 수집 데이터에서 계산한다. 서술의 각 문장은 `refKey`(실제 기사 제목의 부분 문자열)로 기사와
결합되며, **대응 기사를 못 찾으면 빌드가 중단된다** — 근거 없는 문장을 통과시키지 않기 위해서다.

### 실제로 이 가드가 잡아낸 것

1. 서술 4개 문장의 `refKey` 불일치 → 중단. 제목 표기(따옴표·"개혁 아니다" vs "개혁이 아니다")를 확인해 수정
2. **관련성 필터가 핵심 기사를 통째로 누락** — 한국 대학명은 '대학'이 아니라 '대'로 끝나서
   (충남대·서울대·공주대) `/대학/` 패턴에 안 걸렸다. `UNIV_NAME` 패턴 추가로 해결
3. **대학 언급량 오탐** — '서울대 10개 만들기'는 사업명인데 서울대 기사로 집계됐다(40건 → 14건).
   `PROGRAM_NAMES` 로 사업명을 치환한 뒤 카운트하도록 수정
4. **Tier 배지 불일치** — 서술이 준 tierName('경계')과 집계가 계산한 tier(1)가 어긋났다.
   심각도는 서술이 아니라 집계가 정하도록 변경

### 남은 캘리브레이션

위험신호 임계값(Tier 3 ≥32%, Tier 2 ≥25%)은 샘플 데이터 기준이라 실제 분포(9.2%)와 맞지 않는다.
3~4주치를 쌓아 분포를 본 뒤 재설정해야 한다. 지금은 `trend: "baseline"` 으로 표기만 하고 있다.

## 실제 시계열 · 일일 브리핑 (`series.mjs`, `daily.mjs`)

구글 뉴스 RSS는 `after:`/`before:` 로 과거 구간 검색을 지원한다. 이를 이용해 **8주치를 소급 수집**했다.

```bash
for r in "2026-08-28 2026-09-04" "2026-08-21 2026-08-28" …; do node collect.mjs --from $1 --to $2; done
node aggregate.mjs w37   # 완성 주차(서술 포함)
node series.mjs          # 과거 주차 + 임계값 재설정 + 전주 대비
node daily.mjs           # 일일 브리핑
node build.mjs && node pdf.mjs
```

기획용 샘플 주차는 전부 제거했다. 현재 리포트의 8개 주차는 모두 실데이터다.

### 비교 가능성

과거 주차는 구글 뉴스로만 소급할 수 있다(언론사 RSS는 최신 50건만 제공). 그래서 **주차 간 비교
지표는 구글 소스로 통일**해 계산하고(`comparable`), 최신 주차의 본문·각주에는 언론사 RSS까지
포함한 전체 수집분을 쓴다. 추이 차트도 `comparable` 을 쓴다.

### 임계값

샘플 기준 임계값(Tier3 ≥32%)은 실제 분포(1.4~11.7%)와 전혀 맞지 않았다. 사분위로 다시 뽑았더니
표본이 8주뿐이라 Tier4(6.9%)와 Tier3(6.7%)이 붙어 무의미해졌다. 최종적으로 **중앙값 + MAD**
(최소 간격 1.0%p)로 산정한다. 현재 Tier4 ≥8.7% / Tier3 ≥7.5% / Tier2 ≥6.3%, **표본 8주차의
잠정값**이며 `data/thresholds.json` 에 근거와 함께 기록된다.

### 일일 브리핑

`dist/daily.html`. 주간과 같은 수집본을 날짜로 쪼개므로 추가 수집이 필요 없다.
헤더 버튼은 **주간 리포트 / PDF 다운로드** 두 개다. 일일 브리핑에는 지도가 없어
'현재 화면 그대로 인쇄'가 의미 없으므로, 인쇄 버튼 대신 **빌드 때 미리 구운 PDF** 를 내려받게 했다.
**일간은 LLM 서술을 두지 않는다** — 집계와 기사 목록만 제공하고, 해석·전망·권고는 주간이 맡는다.
매일 돌려도 비용이 들지 않고, 수치 외의 판단이 들어가지 않는다.

일간은 하루 표본이 18~200건으로 분산이 커서 주간 임계값을 쓸 수 없다. **일별 분포로 임계값을
따로 산정**하고, **30건 미만인 날은 등급을 매기지 않는다**(`표본 부족` 표시). 분야별 위험신호 비율도
5건 미만이면 숨긴다 — 1건짜리 분야가 '위험신호 100%'로 표시되는 것을 막기 위해서다.

### 제외 지표

`data/sources.json` 의 `_excluded` 에 기록한다. 배경 지표 블록을 다시 구성할 때 이 목록을 먼저 확인할 것.
현재: **AI 마에스트로 누적 수료** (2026-09-11 제외).

```bash
node feeds.mjs --days 14   # 기관 공식 채널 → data/feeds/<date>.json
node aggregate.mjs w37     # 워치리스트 언급 집계까지 함께 수행
```

### 개인 SNS를 수집하지 않는 이유

**기술적으로 막힌다.** 2026-09-11 직접 확인:

| 플랫폼 | 결과 |
|---|---|
| X(트위터) | API 유료. Nitter(무료 우회) `nitter.net` **HTTP 410 종료** |
| 페이스북·인스타그램 | Graph API 사전 승인 필요. 공개 페이지도 Page Public Content Access 심사 |
| 네이버 블로그 RSS | ✅ 교육부 50건 / 과기정통부 50건 |
| 유튜브 채널 RSS | ✅ `feeds/videos.xml?channel_id=UC…` 인증키 불필요 |

**제도적으로도 피해야 한다.** 국립대(공공기관)가 특정 인물, 특히 정치인의 개인 계정을 상시
수집·저장·내부 배포하면 정치적 중립 의무(국가공무원법 §65, 교육기본법 §6)와 개인정보 처리
문제가 생긴다. 공개된 게시물이라도 체계적 수집·DB화는 '처리'에 해당한다.

**그래서 이렇게 한다.** 인물은 **직책으로 추적**하고(`watchlist.json` 의 `persons`), 발언은
기사·보도자료 같은 **공적 기록에서만** 집계한다. 피드로 당겨오는 것은 **기관 공식 채널뿐**이다.

현재 집계 결과: 최교진 교육부 장관 8건 · 교육부 28건 · 과기정통부 4건 · 부산시 3건 · 국회 교육위 2건.
이름이 비어 있는 직책(교육부 차관, 국회 교육위원장, 부산대 총장 등)은 `watchlist.json` 에 채우면
자동으로 집계에 들어간다.

## 지도 — 내 위치 / 인쇄 반영

**내 위치**: 지도 좌상단 `◎` 버튼. 누를 때만 권한을 요청하며 자동 요청은 하지 않는다.
좌표는 브라우저 안에서만 쓰이고 서버로 전송되지 않는다. 표시와 함께 기준 대학(부산대)까지의
거리를 계산해 보여준다.

**인쇄 반영**: 헤더 버튼이 둘로 나뉜다.

- **표준 PDF** — 빌드 때 헤드리스 Chrome 으로 미리 구운 파일(`dist/pdf/`). 기본 지도 화면이며
  **열람자의 위치는 들어가지 않는다**(서버에서 생성되므로 애초에 알 수 없다).
  `pdf.mjs` 가 주간·일간 두 산출물을 한 번에 굽는다 (`--only weekly|daily` 로 하나만 지정 가능).
- **현재 화면 PDF** — `window.print()`. 지금 보고 있는 **지도의 중심·확대·내 위치 표시까지 그대로**
  인쇄/PDF 저장된다.

인쇄 시 컨테이너 크기가 바뀌면 Leaflet 이 같은 중심이라도 다른 영역을 그리므로,
`beforeprint` 에서 중심·확대를 저장 → `invalidateSize()` → 저장값으로 복원한다.
인쇄용 지도 높이도 화면과 같은 460px 로 맞췄다(기존 300px 축소를 제거).
`◎` 버튼은 인쇄물에서 숨긴다.

> 내 위치를 표시한 채 '현재 화면 PDF' 로 저장하면 그 PDF에 위치가 남는다. 외부 공유 전 확인할 것.

## 지도 — 대학별 키워드 호버

마커에 마우스를 올리면 그 대학의 **주요 키워드**가 뜬다. 키워드는 서술이 아니라
**그 대학을 언급한 기사 제목에서 코드가 집계**한다(`aggregate.mjs` 의 `uniDetail`).
조사가 붙은 토큰은 원형으로 합치고('탈락에'→'탈락'), 교명 자체와 불용어는 제외한다.

표시 내용: 위험신호 등급 배지 · 주목도 · 언급 건수 · 위험신호 건수(비율) · 키워드 상위 5개 · 대표 기사.

### 마커 인코딩을 두 축으로 분리

처음에는 언급량 하나로 크기와 색을 모두 정하고 '위기/경계/주의/관심'으로 불렀다.
그 결과 **부산대가 62건 언급으로 '위기'로 표시**됐는데, 정작 내용은 '서울대 10개 만들기' 선정과
AI스타펠로우십 121억 확보였다. 언급이 많다는 이유로 호재가 위험으로 읽히는 오류다.

그래서 두 축으로 나눴다.

- **크기 = 주목도** (주간 언급량): 최다 / 많음 / 보통 / 적음
- **색 = 위험신호 비율** (crisis+warning 비중): 없음(초록) / 일부 / 있음 / 높음(빨강)

현재 주차 결과 — 부산대는 **가장 큰 초록 마커**(주목도 최다, 위험신호 0/62),
충남대는 **큰 주황 마커**(주목도 많음, 위험신호 6/34 = 17.6%)로 통합 무산 국면이 드러난다.

호버 툴팁은 `z-index:1200` 이다. Leaflet 컨트롤(`.leaflet-top` = 1000)보다 위에 와야
`◎` 버튼이 툴팁을 가리지 않는다.

| 경북대 | =481 | 501–600 |

### 수집 방법

- **THE** — 랭킹 페이지가 Next.js 앱이라 `__NEXT_DATA__.props.pageProps.page.rankingsTableConfig.rankingsData.data`
  에 3,118개교 전체가 들어 있다. 여기서 한 번에 추출한다.
- **QS** — 봇 차단(HTTP 403)으로 curl·WebFetch 불가. 브라우저로 렌더링한 뒤
  `.new-ranking-cards` 의 `RANK`/`Overall Score` 를 읽는다. 국가 필터(`?countries=kr`) 사용, 페이지 넘김 필요.
- 둘 다 **연 1회 수동 갱신**이 현실적이다. 자동화하려면 헤드리스 브라우저가 필요하다.

### 이전에 사라졌던 이유

배경 지표(KPI) 블록은 원래 기획용 샘플 주차에만 들어 있었다. `series.mjs` 가 샘플 주차를
실데이터로 전량 교체하면서 함께 지워졌고, `aggregate.mjs` 는 완성 주차의 `kpis` 를 빈 배열로 두고 있었다.
이제 `aggregate.mjs` 가 `rankings.json` 을 읽어 **배경 지표(부산대)와 지도 마커 양쪽에** 채운다.

참고로 초기 샘플에 넣었던 THE 순위(801–1000)는 **실제와 달랐다**(실제 501–600).
QS 449 는 우연히 맞았다. 샘플 수치를 실측으로 교체한 이유다.

## 세계대학랭킹 패널 + 지도 레이어

```bash
node worldrank.mjs --top 200 --the 2024,2025,2026 --qs 2027
```

**334개교 · 좌표 319건(39개국) · THE 3개년 패널 · QS 238건** 수집. 지도 오른쪽 위 **🌐** 버튼으로
세계 랭킹 레이어를 켜면 QS·THE에 오른 대학의 **위치와 순위**가 표시된다(순위대별 색: 1–50 / 51–200 /
201–500 / 501+). 마커에 마우스를 올리면 국가·QS·THE, 클릭하면 **THE 3개년 추이**까지 나온다.

### 패널 구조

```json
"the": { "2024": {"rank":"501–600"}, "2025": {"rank":"501–600"}, "2026": {"rank":"501–600"} }
```

연도를 키로 두어 추이를 볼 수 있다. THE 는 연도별 URL(`/world-university-rankings/<년>/world-ranking`)을
돌며 수집하고, QS 는 현재 연도만 지원한다(연도별 URL 미확인).

### 수집 방법과 함정

- **THE** — `__NEXT_DATA__.props.pageProps.page.rankingsTableConfig.rankingsData.data` 에 3,118개교 전체가 있다.
- **QS** — curl·WebFetch 는 403. 브라우저 렌더링 후 `.new-ranking-cards` 파싱. 페이지당 30개라
  상위 200까지 7페이지를 넘기고, 한국 대학은 순위와 무관하게 `?countries=kr` 로 한 번 더 훑는다.
- **좌표** — QS·THE 어디에도 없다. **Wikidata SPARQL(P625)** 로 라벨/별칭 매칭 후,
  실패분은 검색 API 로 2차 보강한다. 최종 매칭률 96%.

**겪은 함정 두 가지.**
1. 브라우저 코드를 JS 템플릿 리터럴 안에 넣었더니 정규식 이스케이프가 깨져 **조용히 0건**이 나왔다.
   에러도 안 났다. 그래서 브라우저에서 돌릴 코드는 `src/browser/*.js` 로 분리해 파일째 읽어 넘긴다.
2. QS 순위 라벨이 **대화형 브라우저에서는 `RANK`, 헤드리스에서는 `Rank`** 로 렌더된다(CSS
   text-transform 차이). 대소문자 구분 정규식이라 203건 전부 `rank: null` 이 됐다. `/i` 플래그로 해결.

## 중앙일보 대학평가 패널

`data/joongang-ranking.json` — 거점국립대 10개교의 **2021~2025년 종합평가 순위**.
지도 마커 호버의 보라색 `중앙` 배지와 배경 지표에 함께 표시된다.

**출처 주의**: 전용 사이트 `univ.joongang.co.kr` 가 응답하지 않아 원자료를 직접 받지 못했다.
현재 값은 **나무위키(2차 출처, 이용자 편집)** 경유다. QS·THE 와 달리 공식 페이지에서 직접
수집한 값이 아니므로 **대외 인용 전 원자료 대조가 필요하다.**

(`url` = 실제 참조한 나무위키 문서, `primaryUrl` = 응답 없는 원자료 사이트).

연도별 공표 범위가 다르다(2021·2022년 40개교, 2023·2024년 20개교, 2025년 30개교).
공표 범위 밖은 `null`(미등재)이며 **순위 하락을 뜻하지 않는다.**

## 30~36주 본문 생성

## 모바일 최적화

375px(아이폰 표준)과 360px에서 실측해 고쳤다. 브레이크포인트는 **640px**(모바일)과
**360px**(초협소) 두 단계이고, 기존 860px(태블릿)은 그대로 둔다.

### 실측 전/후

| 항목 | 전 | 후 |
|---|---|---|
| 헤더 높이 | 194px | **124px** |
| 제목 줄 수 | 3줄 | **1줄** |
| 버튼 | 48×114 (세로로 한 글자씩) | **109×36 가로 3분할** |
| 사이드바 | 180px (2행 랩) | **95px (가로 스크롤 칩)** |
| 부문별 영향표 | 309px 에 7열이 눌림 | **660px + 가로 스크롤** |
| 추이 그래프 | 301×45 (라벨 4px) | **560×84 + 가로 스크롤** |
| 페이지 가로 스크롤 | — | 없음 |

### 핵심은 CSS 그리드 함정이었다

모바일 CSS 를 넣었는데도 `innerWidth` 가 **714px** 로 나왔다. 375px 로 강제해도 마찬가지였다.

원인은 `.shell` 의 그리드 자식이 기본값 `min-width:auto` 라는 점이다. 안쪽 표에
`min-width:660px` 을 주자 그 폭이 그리드 열을 밀어냈고, 레이아웃 뷰포트까지 714px 로 넓어졌다.
그러면 `@media (max-width:640px)` 이 더 이상 매칭되지 않아 **모바일 규칙이 스스로 꺼지는**
순환이 생긴다. `.tbl{overflow-x:auto}` 도 무력해진다.

```css
.shell{grid-template-columns:230px minmax(0,1fr)}
.shell > *{min-width:0}
```

이 두 줄로 해결됐다. 넓은 표·SVG 를 가로 스크롤 컨테이너에 넣을 때는 조상 그리드/플렉스
자식에 `min-width:0` 이 반드시 필요하다.

### 그 밖

- 제목에 `word-break:keep-all` — 한국어를 어절 단위로 끊는다
- 사이드바 주차 목록을 칩 형태 가로 스크롤로 바꿔 상단 점유를 절반으로 줄였다
- 표 하단에 `← 좌우로 밀어서 보기` 안내를 붙였다
- 휠 안내 배지는 모바일에서 숨긴다(휠이 없으므로). 지도는 마커를 **탭하면 팝업**이 뜬다
- 360px 이하에서는 지표 카드가 1열로 떨어진다. 375px 은 2열을 유지한다

## 국내·해외 기사 분리 수집

`collect.mjs` 가 구글 뉴스를 **한국어(국내)와 영문(해외)** 두 갈래로 수집한다.
해외는 국내 이슈의 선행·대조 사례로 읽는다.

```
국내 765건 (구글뉴스 ko 9개 질의 + 언론사 RSS 4곳)
해외 310건 (구글뉴스 en 8개 질의)
```

해외 질의: higher education policy reform / university funding cuts / national university merger /
tuition free policy / generative AI university policy / declining enrollment / regional university
revitalization / world rankings policy.

각 항목에 `region: 'domestic' | 'overseas'` 가 붙고, 리포트의 일자별 기사 묶음이
`거버넌스 · 국내` / `기타 · 해외` 처럼 나뉜다. 분야 분류·위험도 규칙에는 영문 키워드를 함께 넣었다
(`merger`, `funding`, `enrollment`, `closure`, `cuts` …).

### 지역별 자리를 보장해야 한다

상위 N 개만 자르면 건수가 많은 국내가 자리를 다 차지해 **해외가 한 건도 안 보였다**.
지역별로 자리를 나눠(국내 3 + 해외 2) 보장한다.

### 비교 지표는 국내로 통일

주차 간 비교(`comparable`)는 **구글 뉴스 국내 소스로만** 계산한다. 과거 주차에는 해외 수집분이
없어 섞으면 추이가 왜곡된다. 해외 건수는 별도 지표로 따로 보여준다.

### 재수집이 기사를 잃지 않게

RSS 창은 시간이 지나면 오래된 기사를 밀어낸다. 덮어쓰기로 재수집했더니 **서술의 각주 근거가
사라져 빌드가 멈췄다.** 이제 같은 기간 파일이 있으면 합친다(제목 기준 중복 제거).

### 필터가 한 곳에 있어야 하는 이유

`aggregate.mjs` 가 `src/filter.mjs` 를 쓰지 않고 한국어 전용 규칙을 따로 갖고 있었다.
그래서 해외 기사 155건이 전부 탈락했다. 공통 모듈로 통일했다.

## 위험신호 추이 — 막대 + 추세선

막대는 그 주의 수준을, 선은 주차 간 흐름을 보여준다. 둘을 겹쳐야 '얼마나'와 '어느 쪽으로'가
함께 읽힌다. 막대 색은 Tier(관심·주의·경계·위기), 선과 값 라벨은 네이비로 통일했다.

- **막대 폭**은 슬롯의 42%, 최대 46px 로 제한한다. 주차가 적을 때 막대가 지나치게 굵어지는 것을 막는다.
- **y축 눈금**은 0 / 절반 / 최댓값 세 줄. 눈금 단위는 `1·1.2·1.5·2·2.5·3·4·5·6·8·10` 배수에서 고른다.
  1·2·5 배수만 쓰면 최댓값 11.7 에 눈금 20 이 잡혀 위쪽이 크게 비었다.
- 막대 전체 폭에 투명 히트박스를 깔아 막대가 얇아도 클릭하기 쉽게 했다.
- 모바일 최소 폭은 620px(가로 스크롤). 라벨이 겹치지 않는 하한이다.

### 헤더 줄바꿈 함정

`.acts` 는 기본이 `nowrap` 이라, PDF 날짜 드롭다운(`flex-basis:100%`)과 버튼이 한 줄에 눌려
**버튼 폭이 8px 까지 찌그러졌다.** `flex-wrap:wrap` + 버튼 최소 폭으로 해결했다.
일일 브리핑은 드롭다운을 맨 앞으로 옮겨 버튼 두 개가 같은 줄에 오게 했다(헤더 210px → 167px).

## 워치리스트 표시 원칙

등록된 인물은 **이번 주 언급이 0건이어도 카드로 보여준다**. 워치리스트는 '누구를 보고 있는지'
자체가 정보이기 때문이다. 0건 카드는 점선 테두리에 회색으로 표시하고 `0건 · 이번 주 언급 없음`
이라고 적는다. 이름이 아직 등록되지 않아 **집계 자체가 불가능한** 직책만 목록 한 줄로 따로 적는다.

처음에는 `n > 0` 인 인물만 카드로 띄웠는데, 새로 등록한 인물이 화면에서 사라져
'추가가 안 된 것'처럼 보였다.

현재 추적 인물: 최교진 교육부 장관 · 이재명 대통령 · 배경훈 부총리 겸 과학기술정보통신부 장관 ·
전재수 부산광역시장. (국무총리·국무조정실은 고등교육과의 직접성이 떨어져 제외)

## 추이 섹션 접기/펴기

`위험신호 비중 추이` 블록을 `<details open>` 으로 감쌌다. 기본은 펼쳐진 상태이고,
제목을 누르면 접힌다(303px ↔ 56px). 인쇄물에서는 ＋/－ 표시를 숨긴다.
